# 按内容组织项目

用户默认按内容找项目，不按创建日期或聊天记录找项目。新建项目及交付物时采用内容目录；用户明确指定的路径优先。

- 先检查现有目录和 README，优先使用已有主题。命名采用“主题/具体项目”，例如“Kalman/基础模块入门/二维温度估计”；不在项目目录名中添加日期、时间戳、聊天ID或随机后缀。
- 同一项目跨聊天继续使用相同目录。不同内容分别归类，不强行共用一个对话专属文件夹。真正不同的实验以方法、对象或用途区分；确实是独立版本时用有意义的版本号。
- 源代码、模型、配套参数、说明和必要结果放在项目目录中。尊重框架、MATLAB Project、构建工具等要求的固定相对路径，避免为了外观把有关联的文件拆散。
- 临时日志、缓存、备份放入项目内忽略的辅助目录或工作区的本地维护目录，不当作独立项目；不把个人学习过程、简历或机器配置顺带提交。
- 添加或移动项目后更新总览及相关相对链接。脚本相对于自身或项目根目录定位资源，不写死本机路径。

## 整理已有文件

新建项目不意味着自动获准重排其他项目。用户明确要求整理时，先盘点 Git 状态及现有修改，为有价值文件和自动保存文件保留可校验备份，然后按内容移动并检查哈希、链接、资源路径及必要运行入口。保留手工改过的模型；不要为验证迁移运行会覆盖模型的生成脚本。

去掉目录名的日期标记不等于删除研究数据年份、文献年份或历史记录正文中的日期。按内容归类，不机械删除所有数字。

Git 提交需精确选择本次文件并检查缓存、备份和个人资料；只有用户要求上传时才推送。沿用项目既有仓库和分支流程，本技能不额外授权合并、发布或重写历史。
