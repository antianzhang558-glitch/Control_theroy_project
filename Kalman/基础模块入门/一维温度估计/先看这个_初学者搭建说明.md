# 从零搭一个卡尔曼滤波器

先打开 **kalman_beginner_temperature.slx**。这是本次改成的入门版：滤波器在顶层直接展开，没有 MATLAB Function，没有矩阵，只有一个温度状态。位置/速度模型保留在 `../../位置速度估计`，作后续参考。

## 先想一个问题

温度计读数上下跳动，我们希望知道真实温度。真实温度也会缓慢变化，不能简单认定它永远等于某个常数。

我们有两个信息来源：

1. 上一拍的估计：如果温度变化很慢，这一拍应该和上一拍差不多。
2. 这一拍的测量：有新的信息，但是传感器有噪声。

卡尔曼滤波就是先预测，再根据二者的可信程度进行融合。它估计温度，不控制温度，也不会让温度收敛到零。

## 第一步：先造一个温度计

双击“真实温度与传感器”，里面用基础模块实现：

    x(k+1) = x(k) + w(k)
    z(k)   = x(k) + v(k)

x 是真实温度，z 是温度计读数。w 是真实温度每一步的小变化，v 是传感器测量误差。

| 模块 | 关键设置 | 接法 |
|---|---|---|
| Unit Delay：当前真实温度 | 初值20，采样时间0.1 | 输出真实温度x；输入下一步温度 |
| Random Number：温度自然变化w | Mean=0，Variance=0.01，Seed=1234，SampleTime=0.1 | 加到真实温度上，结果送回 Unit Delay |
| Sum：下一步温度 | 两个加号 | 当前温度+w |
| Random Number：测量噪声v | Mean=0，Variance=1，Seed=5678，SampleTime=0.1 | 加到当前真实温度上 |
| Sum：带噪测量 | 两个加号 | 当前温度+v，输出z |

真实温度仅用于检验滤波效果。滤波器能看到的只有z。

## 第二步：先只搭温度估计这一条线

回到顶层，看上半部分。先把增益K想成一个0到1之间的数：

    预测温度 = 上一拍估计温度
    偏差 = 本次测量 - 预测温度
    本次估计 = 预测温度 + K × 偏差

| 顺序 | 模块 | 设置或作用 |
|---|---|---|
| 1 | Unit Delay：上一拍估计 | 初值18，SampleTime=0.1，输出上一拍的估计 |
| 2 | Gain：预测温度 | Gain=1，表示先认为温度没变 |
| 3 | Sum：测量减预测 | 输入符号为+-，正端接z，负端接预测值 |
| 4 | Product：增益乘偏差 | 两个输入相乘，接K和偏差 |
| 5 | Sum：校正温度 | 输入符号为++，相加预测值和修正量 |

“校正温度”的输出就是估计值。把它接回“上一拍估计”的输入，并接到Scope。

**为什么要Unit Delay？** 当前计算完的估计必须等到下一拍才能当“上一拍估计”。直接用电线反馈会形成代数环。

例如，预测20度、测量22度，若K=0.2，则估计为20+0.2×(22−20)=20.4度。K越大，越靠近本次测量；K越小，越靠近预测。

## 第三步：让K自己算出来

下半部分不是另一条温度信号，而是在计算“估计有多不确定”。

- P：估计误差的方差。越大，说明估计越不可靠；它不是温度，也不是实际误差本身。
- Q=0.01：模型认为每一步自然变化带来的方差。
- R=1：模型认为传感器测量误差的方差。

按下面三条公式搭：

    预测不确定度 P_minus = 上一拍P + Q
    卡尔曼增益 K = P_minus / (P_minus + R)
    校正后不确定度 P = (1-K) × P_minus

| 模块 | 设置或接法 |
|---|---|
| Unit Delay：上一拍不确定度P | 初值4，SampleTime=0.1 |
| Constant：过程方差Q | 值0.01 |
| Sum：预测不确定度 | 上一拍P + Q |
| Constant：测量方差R | 值1 |
| Sum：预测方差加R | P_minus + R |
| Divide：计算卡尔曼增益K | 分子接P_minus，分母接P_minus+R |
| Constant：常数1 | 值1 |
| Sum：一减K | 正端接1，负端接K |
| Product：校正不确定度 | (1-K) × P_minus |

把校正后的P接回“上一拍不确定度P”的输入。把计算出的K送到上半部分“增益乘偏差”的另一个输入。

现在两条线就联系起来了：**上面算温度，下面算上面该相信测量多少。**

初始化时把18度当作上一拍估计、把4当作上一拍P，第一拍先做预测，所以第一拍P_minus=4.01、K=4.01/5.01≈0.8004。本例A=1，因此“预测温度”只是乘1；更复杂的模型才会出现状态转移矩阵。

## 第四步：运行和看结果

仿真设置：Fixed-step，求解器discrete (no continuous states)，步长0.1，停止时间30。

- “温度对比”Scope的输入1/2/3依次是真实值/测量值/估计值。
- “增益K与不确定度P”Scope分别显示K、P。两者在本例参数下会逐渐重合，因为R=1且标量测量系数为1，此时P=K×R；这不是一般情况下二者总相等。
- 生成脚本中的To Workspace模块只负责记录数据，不属于滤波算法；已保存的教学模型省略了这些记录模块，直接用Scope观察即可。
- beginner_response.png是已运行的曲线，beginner_model.png是模型接线图。
- build_beginner_kalman.m可重新生成并验证模型。它会重建入门模型，因此手工改好模型后，请先另存一个名字再运行生成脚本。

建议先沿着“上一拍估计 → 预测温度 → 校正温度 → 保存到下一拍”走一遍，再看P和K的计算。

## 三个小实验

1. 把初始估计18改成10，观察估计如何靠近真实温度。真实值初值仍为20。
2. 只把滤波器里的R从1改成10，保持传感器噪声不变。滤波器会认为传感器更不可靠，K通常变小，估计更平滑，也可能跟随更慢。
3. 恢复R=1，只把滤波器里的Q从0.01改成0.1。滤波器会认为温度更容易变化，K通常变大，估计更跟随测量，也会更抖。

这些是在调整滤波器的假设。若想改变真实传感器噪声，还要改子系统里对应Random Number的Variance。Q、R都是方差，例如R=1对应标准差1，R=4对应标准差2。
